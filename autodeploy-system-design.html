AutoDeploy 系统设计图集

基于 TensorRT-LLM commit e7eb2de0e1b（AutoDeploy 移除前最后版本）源码绘制；主仓库已由 PR #19028 将其剥离为独立包 Paragraf/llmc。

图 1 · 系统分层设计

  • 核心策略：HF 原始模型直接作输入，优化全部移入图变换流水线；运行时复用同一个 PyExecutor。
  • shim 是手工装配路径：create_autodeploy_executor 逐项拼 PyExecutor kwargs——历史漏洞（漏传 garbage_collection_gen0_threshold）即源于此。

图 2 · 运行时线程模型

  • 事件循环错误传播：worker 抛异常（如 KV OOM）→ 存入 _event_loop_error → 客户端线程 re-raise，防止挂死。
  • MPI 线程安全：所有 MPI_Comm_dup 必须在 worker 线程启动前于主线程完成，避免竞态。

图 3 · 数据结构总览

  • transforms: Mapping[name → kwargs]
  • 优先级: CLI > yaml-extra > registry > default.yaml
  • model / world_size / kv_cache_config
  • speculative_config / attn·compile backend

TransformConfigtransform 契约

  • stage: Stages（强制排序依据）
  • run_per_gm / enabled / skip_on_error
  • requires_clean_graph / requires_shape_prop
  • run_graph_cleanup / run_shape_prop
  • expect_mem_change（显存审计）

SharedConfig全流水线共享

  • local_rank / world_size
  • dist_config: DistConfig(tp·ep·pp)
  • enable_attention_dp

Stages有序枚举

  • FACTORY→EXPORT→POST_EXPORT
  • →PATTERN_MATCHER→SHARDING
  • →WEIGHT_LOAD→POST_LOAD_FUSION
  • →CACHE_INIT→VISUALIZE→COMPILE

② 流水线状态（挂在 GraphModule 上）

mod.meta["_autodeploy"]图级元数据

  • transform_history: name→TransformInfo
  • mem_history: name→{pre,post MemStats}
  • 前缀恢复 / pipeline cache key 依据

TransformInfo变换结果

  • skipped / num_matches
  • is_clean / has_valid_shapes
  • 合并语义: | (pre) 与 & (post)

③ 运行时对象与队列

CachedSequenceInterfaceshim 核心

  • info: SequenceInfo
  • kv_cache_manager (C++)
  • kv_group_windows / attention_type
  • kernel_handles_cyclic_swa

SequenceInfo每迭代 nest_sequences 写入

  • input_ids / cu_seqlen / input_pos
  • batch_info: prefill·extend·decode (n,tokens)
  • cache_loc_per_pool / cu_num_pages_per_pool
  • seq_len_with_cache_per_pool / slot_idx
  • named_args = 模型 kwargs (**extra_args)

LlmRequest请求对象

  • py_request_id / py_seq_slot / py_batch_idx
  • context_current_position（块复用起点）
  • context_chunk_size（chunked prefill）
  • py_prompt_len / py_draft_tokens
  • py_multimodal_data / is_cuda_graph_dummy

ScheduledRequests调度产物

  • context_requests / generation_requests
  • extend_requests（spec dec）
  • batch_size / can_run_cuda_graph
  • generation_requests 可被 dummy 填充

队列与同步线程间

  • ExecutorRequestQueue(dist 感知)
  • WaitingQueue（策略可换）
  • responses{} + result_wait_queues
  • response_lock / response_cv
  • control_request_barrier / shutdown_event

ResourceManager资源注册表

  • KV_CACHE_MANAGER: KVCacheManager(C++)
  •   tokens_per_block / mamba_cache_index
  • SEQ_SLOT_MANAGER: SeqSlotManager
  • move_to_end: KV 最后释放
  • 设计要点：配置（Pydantic strict 化）→ 图级元数据（TransformInfo 携带 clean/shape 状态避免重复清理）→ 运行时 C++/Python 边界（KVCacheManager 走 pybind）。

图 4 · 数据流阶段图

  • 构建期本质：数据形态五连跳——HF 权重 → meta 空模型 → FX 图 → 统一 IR 图 → 编译产物；权重在切分后才加载（直接按 shard 读）。
  • 运行期本质：LlmRequest（Python 对象）→ SequenceInfo（扁平张量 kwargs）→ CUDA graph 重放；decode 循环不重建请求，只写回 token。
