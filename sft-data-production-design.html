0. 阅读指引

本文面向初次接触 LLM 训练侧的工程师。全文涉及的英文缩写在第 1 章术语表中集中解释；正文中每个术语首次出现时也以「缩写（全称，中文含义）」的形式标注，方便顺着读。表内「一句话解释」按本文语境给出，力求够用而非百科式完整。

1. 术语表（专有名词速查）

1.1 任务与场景

缩写 / 术语全称一句话解释
NLUNatural Language Understanding，自然语言理解把用户自然语言转成机器可执行结构（意图 + 槽位）的模块，即本文训练的模型要完成的任务

WTP184—当前车载项目代号，NLU 网关的宿主平台
OTAOver-The-Air，空中下载升级车机远程更新机制；模型与协议需可版本化追溯

缩写 / 术语全称一句话解释

SFTSupervised Fine-Tuning，监督微调用「输入 + 标准答案」成对数据教已训练好的模型适配特定任务，本文主题

few-shot少样本示例在 prompt（提示词）里给模型若干示例帮它理解任务
HF / transformersHugging Face / 其模型库模型与数据集的事实标准托管平台；transformers 是其 Python 训练/推理库

Qwen3通义千问 3（阿里开源模型系列）本文基座；0.6B 版是蒸馏（用大模型输出训练）产物的小模型
tokenizer / token分词器 / 词元tokenizer 把文本切成 token（最小处理单位）并映射为整数 ID；「训推一致」的关键部件
chat template对话模板把 messages（角色对话列表）渲染成模型输入格式的 Jinja2（Python 模板语言）脚本；训练与推理必须用同一份
/no_think—Qwen3 家族支持的软开关：写在消息尾部可抑制思考段输出；SFT 后可解除

1.3 量化与部署

缩写 / 术语全称一句话解释
llama.cpp—C++ 实现的 LLM 推理引擎（含 GGUF 格式与量化工具链），端侧部署首选
GGUFGPT-Generated Unified Formatllama.cpp 的模型文件格式：权重、tokenizer、chat template 打包单文件
量化quantization把权重从高精度浮点压到低位整数以缩小体积、加快推理；有精度代价
Q8_0 / Q6_K / Q4_K_M—llama.cpp 量化格式名：数字≈每权重比特数；K = 超块（分组二次压缩 scale）家族；_M = 敏感层用高位宽的混合配方
bpwbits per weight，每权重比特数量化程度的通用度量；越大越准、越慢、越大
imatriximportance matrix，重要性矩阵用领域数据统计的各权重重要性，指导量化把误差分配到不重要的位置
GBNFGGML Backus-Naur Formllama.cpp 的文法约束语言；JSON Schema（JSON 结构描述规范）可转成它，推理时强制模型只能输出合法格式
greedy贪心解码每步都取概率最高的 token；结果可复现，评测必须用它
seed随机种子固定后采样过程可复现；与 greedy 配合保证评测可对照
KV cacheKey-Value cache，键值缓存推理时缓存的注意力中间结果，随上下文长度增长

1.4 数据与评测

缩写 / 术语全称一句话解释
schema模式（结构定义）nlu_10 输出的字段、类型、枚举值的正式定义；定稿后即「契约」
validator校验器检查数据/输出是否符合 schema 的程序；线上解析、训练数据质检共用同一份（三位一体）
codec编解码器（coder-decoder）协议的编/解码实现；本项目按显式枚举组织（不提前做通用框架）
train / eval训练集 / 评测集分别用于训练和验收的数据子集；切分不当会「泄漏」导致评测虚高
泄漏data leakage评测样本（或其变体）出现在训练集，评测数字失真
accaccuracy，准确率分类正确的比例；本文指 intent（意图）识别准确率
F1F1-score精确率（precision）与召回率（recall）的调和平均，衡量槽位抽取质量
PPLPerplexity，困惑度语言建模误差的通用指标；量化前后对比用（ΔPPL）
A/B对照实验同一评测集上对比新旧两版方案
标注 / 弱标签labeling / weak label为数据打标准答案；弱标签指来自规则系统等低成本来源、未经人工确认的答案

2. 结论速览

  • SFT 数据生产有七个阶段（见下图）：契约冻结 → 三源采集 → 质量闸门 → 渲染切分 → LoRA SFT → 部署产物链 → 全链路评测 → 上车。
  • 顺序铁律：schema（结构定义）v2 与 chat template（对话模板）同时冻结后才开工产数据——任何变更都会导致全部标注作废重产。
  • 主力数据源是逆向合成（先定 label 标准答案、让大模型反向写用户说法）：标签天然正确、覆盖可控、可大批量。
  • 车载特有必做项：ASR（语音识别）噪声增强——模型要学「带噪声的输入 → 干净的标准输出」。
  • 训后闭环：SFT 之后必须重跑量化评测（锚定 Q8_0），全过才上车替换，此时可解除 /no_think 依赖。

3. 阶段 0：契约冻结（双冻结铁律）

SFT 数据的本质是成对的 (输入, 标准输出)，标准输出就是 nlu_10 v2 格式的 JSON（JavaScript Object Notation，一种轻量数据交换格式）。因此开工前必须冻结两样东西：

冻结项为什么必须先冻结变更代价
schema v2（nlu_10 结构定义）每条数据的 label（标准答案）格式就是它；字段/枚举一改，全部标注作废数百上千条 × 人工抽检成本全部重付
chat template（GGUF 内嵌模板）模型学的是「该模板渲染出的输入分布 → 该格式的输出分布」；模板换了，训练/推理分布错位，微调收益打折全部样本重渲染重训，且线上 GGUF 需同步换版

这就是《schema 调优设计方案》中「顺序铁律」的展开：协议与模板都是先冻结、后产数据；任何变更走版本号并触发数据重产流程。模板唯一事实源在 GGUF 元数据里，工程配置中不留第二份拷贝（第二份必然漂移）。

4. 阶段 1：数据规格（Data Spec）—— 先定覆盖再动手

数据生产不是「有多少收多少」，而是先写覆盖矩阵，按矩阵验收：

维度要求说明
intent 覆盖每个意图 ≥ 50–200 条总盘 1k–10k 起步；0.6B 域任务质量 > 数量
slot 组合覆盖每个意图的槽位：出现 / 缺失 / other 兜底 三态都有实例缺失态最容易被遗漏，专门造
边界对近义意图成对出现「打开空调」→ hvac_on，与「打开空调 App」→ app_open，对照着喂
多轮上下文带 history（历史对话）的样本占 20–30%指代消解用例（上一轮「导航去公司」→ 本轮「换个避开高速的」）；history 按线上网关格式渲染
ASR 噪声增强15–25% 的样本带仿真噪声见 5.3 节规则表
风格多样性同一语义 ≥3–5 种说法命令式 / 口语化 / 省略主语 / 带语气词

5. 阶段 2：三源采集

5.1 三源与配比

来源方式优点缺点建议占比
真实日志（脱敏）线上 query 日志 → 人工/大模型复核标注分布最真实量少、隐私脱敏、长尾偏斜20–30%
逆向合成（主力）先采样 (intent, slot 组合)，让云端大模型反向写多样用户表达标签天然正确（构造时写死）、覆盖可控、可大批量风格偏书面，需显式要求口语化40–50%
正向标注 + 影子数据收集 query 让大模型标 intent/slots；或用现有规则 NLU 的历史结果当弱标签接近真实分布标签可能有错~30%
所有来源的 label 一律过 schema v2 validator 自动校验（三位一体中的校验器第二次复用：线上解析、训练数据质检共用同一份代码）。正向标注来源另加 5–10% 人工抽检校准大模型标注质量，抽检不合格率 > 3% 时该批次废弃重标。

5.2 逆向合成 prompt 模板

你是车载语音助手的用户模拟器。请根据给定的语义标签，写出 1 条真实车主
会说的中文口语。要求：
1. 只输出这句话本身，不要解释；
2. 风格从以下随机选择：命令式 / 口语省略 / 带语气词（啊、呗、麻烦）；
3. 数字可用中文或阿拉伯数字随机表达；
4. {带 ASR 噪声} 时请引入 1 处同音字或近音字错误；
5. 槽位缺失时自然省略，不要编造。

语义标签：intent={intent}
槽位：{slots_json}
风格：{style}
噪声：{with_asr_noise}

调用侧按覆盖矩阵采样 (intent, slots, style, with_asr_noise) 组合，批量生成后与构造时写死的 label 组成成对数据——label 不经过任何模型，因此不可能标错。

5.3 ASR 噪声仿真规则（车载特有）

噪声类型示例说明
同音字替换空调 → 空掉最常见的转写错误，重点覆盖
近音替换导航 → 道航拼音相近的错字
数字转写漂移二十四度 / 24 度 / 二四度数字的 ASR 输出形态不稳定，label 侧仍输出规范 "24"
断句/粘连把空调打开一下 → 把空调打开一下下、空调打开语尾重复或截断
噪声只进 user 输入侧，assistant 标准答案永远是干净的规范输出——模型要学的正是这层「清洗映射」，这是车载 NLU 数据与普通 chatbot 数据最大的差异。

6. 阶段 3：质量闸门（不过就回炉）

闸门检查内容实现
schema 校验枚举合法、absence 语义唯一、无多余字段validator 全量自动跑（零人工成本）
去重合成数据最易重复两级：label 完全相同 + 文本编辑距离阈值
分布对齐intent 分布与线上真实分布对照长尾 intent 可超采样，但主干比例不得失真
泄漏检查训练集与评测集重叠n-gram 重叠扫描；评测 query 及其变体绝不进训练集
覆盖矩阵验收第 4 章矩阵逐格打勾缺格即回炉采集，不许带病进训练

7. 阶段 4：渲染与切分

每条样本转成 messages（角色对话列表）——与线上 BuildRequest 的 JSON 结构完全同构，训练的正是推理时真正要做的任务：

图 2 · 一条训练样本的解剖：messages 结构 → 模板渲染 → loss mask

三个工程要点：

  1. 同一模板渲染：训练时 LLaMA-Factory 的 template: qwen3 与线上 GGUF 内嵌模板同源——这是「契约桥」在训练侧的执行点。
  2. loss 只算 assistant 段（loss mask 见图 2 底行）：模型不学复述输入，只学生成标准答案。多轮样本中 history 段同样 mask 掉。
  3. train / eval 按 intent 分层切分（stratified split，分层抽样）：每个 intent 按比例切，防止某个 intent 全进训练集导致评测集测不到它。评测集固定后冻结入库，任何人不许改。

8. 阶段 5：LoRA SFT 实操（LLaMA-Factory）

8.1 数据集登记

{
  "nlu10_sft_v1": {
    "file_name": "nlu10_sft_v1.json",
    "formatting": "sharegpt",
    "columns": { "messages": "conversations" }
  }
}

数据文件用 sharegpt 格式（多轮 messages 列表），与网关的请求 JSON 同构，转换零成本。

8.2 训练配置（关键参数与理由）

model_name_or_path: Qwen/Qwen3-0.6B
stage: sft
do_train: true
finetuning_type: lora
lora_rank: 8            # 域任务 8 够用；不收敛再升 16
lora_alpha: 32
lora_target: all        # 覆盖全部线性层
template: qwen3         # 与线上 GGUF 模板同源 —— 契约点
dataset: nlu10_sft_v1
cutoff_len: 1024        # 单轮+短多轮足够
packing: false          # 短结构化样本不做拼接
train_on_prompt: false  # loss 只算 assistant 段（图 2 的 mask）
num_train_epochs: 2.0   # 盯 eval loss，一回升立即早停
per_device_train_batch_size: 16
learning_rate: 1.0e-4
val_size: 0.05          # 从训练集再留 5% 做 val loss 监控
0.6B 规模普通 LoRA 单卡显存毫无压力（QLoRA 都不需要）；保留 LoRA（而非全参微调）的价值在于按域版本管理——nlu 域、后续新域各自一个补丁，回滚与灰度都按补丁走。

9. 阶段 6–7：训后闭环与上车

SFT 产出的 LoRA merge（合并）回基座后，走标准部署产物链：

merge (LLaMA-Factory) 
  → convert_hf_to_gguf.py        # HF 权重 → GGUF
  → llama-imatrix                # 校准集就用这批 NLU query（同域！）
  → llama-quantize               # 产 Q6_K / Q8_0 候选
  → llama-perplexity / llama-bench / 业务评测集
  → 全链路验收 → 上车
闭环要点说明
SFT 后必须重跑量化评测输出分布变了，量化敏感度随之变化；指标：格式遵守率 / intent acc / slot F1，对比 Q8_0 锚点（对照基准），greedy + 固定 seed
imatrix 校准集 = 训练数据同域量化误差按 NLU 分布分配，而不是通用文本分布
上车后解除 /no_think 依赖训练数据的 assistant 段天然无 think（思考）——SFT 后非思考输出成为模型「母语」，/no_think 从必需品降级为保险丝；ParseResponse（解析）前置剥离逻辑常驻兜底
retry-rate 面板观察归零趋势SFT + grammar 双保险下，校验失败率应趋近 0；若爬升按「失败分桶」面板归因（详见《schema 调优设计方案》第 11 章）

10. 数量与验收门槛

指标门槛测量方式
数据量1k–10k 起步，每 intent ≥ 50–200覆盖矩阵验收
标注质量validator 通过率 100%；人工抽检错误率 < 3%闸门自动 + 抽检
格式遵守率（训练后）≥ 99.5%（相对 SFT 前的 ~95%）评测集，greedy + seed
intent acc 提升SFT 后相对基座 +10pp 量级为预期合理区间（判断失败轴的修复）评测集对照
slot F1 提升长尾切片（低频 intent/槽位）≤ 5pp 落后于主干分层切片统计
量化损失ΔPPL ≤ 5%（对 Q8_0）；acc/F1 跌幅 ≤ 1pp量化前后对照

11. 常见坑（按踩坑频率排序）

#坑症状规避
1schema 没定稿就开标中途改协议，数据作废阶段 0 双冻结，变更走版本号
2训练/评测泄漏评测虚高，上车掉点n-gram 查重 + 评测集冻结入库
3没有 ASR 噪声增强干净数据训出高分，真实语音输入翻车15–25% 样本带仿真噪声
4epoch 跑多格式率升、泛化降（背训练集）epoch 2–3 + eval loss 早停
5训完直接换 GGUF 不重测量化吃掉 SFT 收益而不自知阶段 6 红线：量化评测必重跑
6训练模板与线上不一致训推分布错位，收益打折template: qwen3 + GGUF 单一事实源
